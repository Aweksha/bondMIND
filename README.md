# bondMIND AI

A fixed-income research workstation: security screening, bond analytics, yield curves, and,
in later milestones, explainable ML signals and portfolio scenario analysis.

> **Research tool only. Not investment advice.** The **Treasury yield curve is real**
> (U.S. Department of the Treasury, public domain). The **bonds, issuers, ratings, spreads
> and quotes are synthetic**: they're generated by a deterministic script and priced off
> the real curve. They are not market data. Responses carry `is_synthetic` flags, and the UI
> labels synthetic data everywhere.

## Quick start

Requires Docker Desktop.

```bash
make up            # or: docker compose up -d --build --wait
```

| URL | What |
| --- | --- |
| http://localhost:8080 | Web app |
| http://localhost:8000/docs | API docs (OpenAPI / Swagger) |
| localhost:5432 | PostgreSQL (`bondmind` / `bondmind`) |

On start the API container applies migrations and loads the seed data. Loading is
idempotent, so a restart doesn't load anything twice. `make reset-demo` wipes the data and
reloads it.

### Local development (hot reload)

```bash
make backend-setup   # once: Python venv + deps (Python 3.12+)
make api             # Postgres in Docker, API on :8000 with --reload
make web             # Angular dev server on :4200, proxies /api -> :8000
make test            # backend (pytest) + frontend (vitest)
make lint
```

## Conventions

- Yields and coupons are stored and served in **percent** (`4.25` = 4.25%). Prices are
  **clean, per 100 face**.
- Dates are ISO-8601. Timestamps are stored in UTC.
- Financial values are stored as `NUMERIC` and serialized as JSON numbers.
- Errors always look like `{code, message, details, request_id}`. Every response carries an
  `x-request-id` header.
- Every market observation links to the `ingestion_runs` row that loaded it (lineage).

## Data pipeline

0. `python -m app.ingest.ust_treasury --from-year 2019` downloads the daily Treasury par
   yield curve and writes `data/seed/ust_par_curve.csv`, plus a `.meta.json` file recording
   the source URL, licence and retrieval time. The snapshot is committed, so the app runs
   offline. Tenors that weren't published on a date are left out, never filled in.
1. `python -m app.seed.generate` writes the synthetic bond CSVs from a fixed seed. Each
   bond's yield is the real curve yield plus a synthetic credit spread. Output is
   byte-identical across runs, and CI checks that.
2. `python -m app.seed.load` validates each record. Valid rows are inserted. Invalid rows go
   to `data_quality_issues`, with the rule that rejected them and the raw record.

The generator **deliberately adds 5 invalid rows** so the quarantine path is always exercised:
one duplicate quote, one negative price, one crossed market (bid > ask), one unknown
security, and one yield entered in bp instead of percent. The real curve file is never
modified. If a snapshot changes, the next load replaces the old demo data automatically. You can see them on the
**Data / Models** page.

### Synthetic universe

- Real U.S. Treasury par curve: up to 14 tenors (1M–30Y), every trading day from
  2019-01-02 to 2026-11-06 (about 25k observations).
- 10 Treasury notes and 60 corporate bonds from 20 fictional issuers across 8 sectors,
  rated AAA–BB. Some issuers have a mid-period rating action.
- Daily bid/ask/mid quotes. Each yield is the curve yield plus the issuer's spread plus
  noise, and each price is computed from its yield with `app/analytics/bond.py`.
- No real ISINs or CUSIPs are used.

## Pricing engine (Requirements 2.0, S2-C)

Code is in `backend/app/analytics/`. `GET /api/v2/engine` returns the methodology labels,
and every valuation response includes them.

- **Bond math** (`bond.py`): cash flows (short first coupons pro-rated), accrued interest,
  clean and dirty price, YTM, Macaulay and modified duration, convexity, and DV01.
- **Curve** (`curve.py`): par yields are never used as discount rates. The par curve is
  bootstrapped to a zero curve: short tenors (6M and under) are treated as zero rates, a
  semiannual par grid is solved node by node, and discount factors are interpolated
  log-linearly between nodes. There is no extrapolation past 30Y. Bonds are priced off
  the zero curve plus a **Z-spread** calibrated to the market price.
- **Scenarios:** shocks are applied to the par yields (linear between shock nodes, flat
  outside them), and the curve is re-bootstrapped. Each bond's spread is held constant by
  default, or shocked if you choose. Effective duration, convexity and DV01 come from
  ±1bp re-pricing. DV01 is signed: the dirty-price change per 100 face for a +1bp move.
- **Validation:** `tests/test_golden_quantlib.py` checks prices, accrued interest, yields,
  durations, convexity, DV01 and full cash-flow schedules against **QuantLib**, an
  independent implementation used only in tests. The cases include stubs, premium bonds,
  negative yields and bonds near maturity.
- **Unsupported instruments** (callable, putable, non-bullet) are rejected with an
  `unsupported_instrument` error. They are never priced approximately.

### v2 API

| Endpoint | Purpose |
| --- | --- |
| `GET /api/v2/curves/{id}/dates` | Dates and tenors that have observations (for date pickers) |
| `GET /api/v2/curves/{id}/observations?dates=&tenors=` | Curve overlays for up to 6 dates. Missing tenors come back as `null`; weekends resolve to the prior day and are flagged |
| `GET /api/v2/securities/{id}/analytics` | Prices, risk measures, Z/G-spread, discounted cash flows, assumptions |
| `POST /api/v2/scenarios/evaluate` | Parallel, twist or key-rate shocks, repricing up to 10 bonds. Returns the input, units, warnings, data version and engine version |

Requests accept camelCase (`baseDate`, `shockNodes`) or snake_case. When one bond fails
(for example an unsupported instrument), it returns an error entry and the other bonds
still price.

### Terminal (`/terminal`)
Search with `/`, select a bond, and the detail and curve-context panels update. Each panel
loads and fails on its own, and a new selection cancels requests still in flight. The
detail panel shows prices, YTM, durations, convexity, signed DV01, Z/G-spread, history
(yield or price, 3M–All, zoom) and discounted cash flows.

### Curve Lab (`/curve-lab`)
- Overlay up to 3 historical dates on the real Treasury curve. Missing tenors show as gaps
  and "n/a", never zero.
- Apply a parallel (±300bp slider or exact value), twist (2Y/10Y) or key-rate shock, and
  hold or shock the credit spread.
- The shocked curve previews instantly. Official prices come from the server and are
  marked "updating…" until they arrive.
- The view (bond, dates, shock) is kept in the URL, so you can share or bookmark it.
- Export the curve table as CSV, the full scenario with its assumptions as JSON, and any
  chart as PNG.

### Tests
- `make test`: backend (pytest, QuantLib golden cases) and frontend unit tests (vitest).
- `make e2e`: Playwright browser tests against the running stack. They cover search to
  detail, overlay gaps, shock and reset, input clamping, out-of-order responses (the latest
  action wins), and a failed valuation leaving the charts intact.

The full scope is defined in the bondMIND AI SRS/PRD, v1.0, and the Requirements 2.0 addendum (7 November 2026).
